# Duplicate listing detection (2026-07-21)

Read-only enrichment, same pattern as Data Centre Fit: no deletions, every
row stays in `dashboard/data/*.json`, a new `dedup` field flags which rows
are duplicates of which, and the dashboard hides non-canonical duplicates by
default with a "Show duplicates" toggle to see everything.

## What was found

Scanning the live 220-row dashboard for exact price+size matches (both > 0)
found **8 groups, 9 duplicate rows**, zero false positives on manual
inspection:

| Pattern | Example | Groups |
|---|---|---|
| Cross-source syndication — an agent we scrape directly also appears via Rightmove Commercial's aggregation | Barnsdales' Doncaster listing, SMC Brownill Vickers' two Sheffield listings, Gifford Dixon's Salford listing — all also present as separate Rightmove Commercial rows | 4 |
| Same-agent relisting on Rightmove itself | Bramleys (Huddersfield) — Longwood Gate listed twice, New North Road listed three times, each with slightly different wording; Knight Frank's Broadfield Road split into two listings by use-class (warehouse vs office) for what's price/size-identical | 3 |

## Fingerprint

`src/dedup/listings.ts`: exact price + exact size as the primary key (a
strong, low-noise signal on this dataset — confirmed manually against all 8
groups), gated by an address-token-overlap check (≥30% shared significant
words) so a coincidental price+size collision between two unrelated
properties wouldn't get merged. 12 unit tests including the real Longwood
Gate, Scotland Street, and New North Road cases as fixtures.

**Canonical selection** (which row stays visible): geocode precision first
(`exact` > `postcode` > `city-centroid` — prefer whichever copy has the best
location data, regardless of source), then prefer a directly-scraped source
over Rightmove's aggregation on a tie, then the more descriptive address.
This isn't a blanket "always prefer our own source" rule — on the Scotland
Street pair, Rightmove's copy actually had real embedded coordinates
(`exact`) while our own SMC Brownill Vickers scrape only had postcode-level
precision, so Rightmove correctly won canonical status there.

## Result

- 220 total rows, unchanged (nothing deleted).
- 211 shown by default (9 hidden as duplicates), toggle available to see all
  220.
- Canonical rows with hidden duplicates show a "+N other listing(s)" tag
  (hover for the match reason); hidden duplicate rows themselves are tagged
  "duplicate" when the toggle is on.

## Ordering note

Same caveat as the other two enrichment scripts: `scripts/dedup-listings.ts`
must run after any fresh base pull (it reads `dedup`-less rows and adds the
field) — if run before `data-centre-fit.ts`/`rightmove-detail-geocode.ts` on
a freshly-regenerated file it still works correctly (dedup doesn't depend on
their output), but re-running the base report scripts afterward wipes all
three enrichment layers and all three need to run again, same as before.
