# Value-Add scoring (2026-07-22)

Read-only enrichment layer measuring price undervaluation vs. market comparables + flood risk. Same pattern as Data Centre Fit: pure function inputs/outputs, reasons always human-readable, weights/thresholds named constants for later tuning.

## Scoring Model

**100-point scale, two components:**

1. **Price vs. Comparables (75 pts max)** — how much cheaper than local median sale price?
   - ≥20% discount: 75 pts
   - 15–20% discount: 60 pts
   - 10–15% discount: 45 pts
   - 5–10% discount: 25 pts
   - At/above median: 0 pts
   - Above median (premium): –10 pts (clamped to 0)
   - Gated by ≥3 comparable samples in postcode (confidence threshold)

2. **Flood Risk (25 pts max)** — Environment Agency zone classification
   - Zone 1 (low, <0.1% annual): 25 pts
   - Zone 2 (medium, 0.1–1% annual): 10 pts
   - Zone 3 (high, >1% annual): 0 pts
   - Unknown: 5 pts (neutral, incomplete data)

**Bands** (thresholds; will retune once real distribution is visible):
- `strong`: score ≥65 (good value, acceptable risk)
- `possible`: score 35–65 (marginal value or higher risk)
- `unlikely`: score <35 (expensive or high risk)
- `insufficient_data`: no comparables or missing postcode

## Data Sources

**Land Registry Price Paid Data** (free, no auth, scheduled download):
- Historical sale transactions by postcode
- Precomputed median prices per postcode
- Stored in `dashboard/data/land-registry-comparables.json`
- Updated at script start; no live API calls during scraping (performance)

**Environment Agency Flood Risk Zones** (free, OGC/WFS endpoint):
- National flood risk classification
- For MVP: postcode-level lookup (coarse) via hardcoded known high-risk areas
- Future: lat/lon precision via WFS query when geocoding improves

## Implementation

**src/scoring/valueAdd.ts**: Pure scoring function
- `scoreValueAdd(input)` → `{ score, band, reasons }`
- No side effects; reasons array explains every point

**src/geo/floodRisk.ts**: Flood risk lookup
- `lookupFloodRisk(lat, lon)` → WFS query (future; MVP returns null)
- `estimateFloodRiskByPostcode(postcode)` → coarse district-level guess

**src/geo/landRegistry.ts** (stub for future):
- Fetches HM Land Registry data
- Precomputes postcode medians
- Stored as reference table for fast O(1) lookup

**scripts/land-registry-fetch.ts**: Orchestrates Land Registry pull + precomputation
- Extracts postcodes from current dashboard data
- Generates mock comparables for MVP (will be replaced with real download)
- Writes `dashboard/data/land-registry-comparables.json`

**scripts/value-add-listings.ts**: Applies scoring to all dashboard rows
- Reads 3 data files + Land Registry comparables
- Computes score for each row
- Writes `valueAdd` field back in place (no deletions)

**Dashboard UI**:
- New filter: "Value-Add Score" (All / Strong / Possible / Unlikely)
- New sort option: "Value-Add Score"
- Card tag: "Value-Add: {band} ({score})" with reasons on hover
- Flood zone info in reasons (informational, not scored in MVP)

## Test Coverage

**test/valueAdd.test.ts**: 8 unit tests including:
- 20%+ discount with sufficient comparables → strong
- Price at/above median → unlikely
- Moderate discounts (5–15%) + varying flood zones → possible
- Insufficient comparables (< 3 samples) → insufficient_data
- Missing price/postcode → insufficient_data
- Score clamping to [0, 100]
- Reason strings for each component
